背景

想在博客的最下方页脚，显示类似 Updated @ 2025-09-12 14:08 · Build a1b2c3d (Toronto, UTC-4) 的信息，每次重新部署时自动更新，不需要手动改。本文记录实现的完整过程和踩坑总结。

效果展示

1. 保证 CNAME 正常保留

Hexo 每次生成会清空 public/，所以 CNAME 必须放在 source/ 目录，不能放在根目录。

这样每次 hexo g 都会自动复制到 public/CNAME，不会丢。

2. 自动生成 build.json

在构建前写入一份 source/_data/build.json，保存：

  • 当前时间（多伦多时区）
  • Git 提交号（短 SHA）
  • 仓库名（GitHub Actions 自动注入）

3. 在页脚插入构建信息

因为 Redefine 主题没有调用 Hexo 的 injector()，所以换成 after_render:html 强插：直接在生成好的 HTML 的 <footer> 里插入信息块。

效果

页脚中会出现一行小字：

  • 时间已转换为多伦多时区，自动切换夏令时/冬令时
  • 提交号在 GitHub Actions 上可点击跳转
  • 时区标注为 text-xs opacity-60，非常低调，不破坏主题的简约风格

4. bookmarks/friends/essays 报错问题

Redefine 主题默认会渲染这几个页面，如果 _config.redefine.yml 没配置，会报错：

  • theme.bookmarks is not iterable
  • theme.links is not iterable
  • theme.essays.sort is not a function

解决方案有三种：

  1. 不需要这些页面：删除 source/bookmarks|friends|shuoshuo，并在导航里去掉菜单项。
  2. 需要页面但暂时没数据：在 _config.redefine.yml 显式写空数组：
  3. 保险丝脚本（可选）：redefine-safe-defaults.js，把未定义的字段兜底成 []。
    它不会覆盖你已有的配置，只在缺失时生效。生产环境配置齐全后，可以删除。

总结

  1. CNAME 放 source/ 才能持久。
  2. scripts/build-footer.js 强插脚本 自动写 build.json 并插入页脚。
  3. 时间转为 多伦多时区，带一个低调的时区标注。
  4. bookmarks/links/essays 要么删除页面，要么写空数组，要么用 redefine-safe-defaults.js 兜底。
  5. 本地和 Actions 部署都能自动更新，无需手动改动。

这就是一套完整的 Hexo Redefine 页脚自动更新时间 & 构建版本方案 🎉
